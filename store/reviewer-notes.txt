No build step: the package contains the source exactly as in the repository (https://github.com/codexjdub/vimov), with no minified or generated code, no remote code and no network requests.

Permissions:
- Content scripts on all URLs: Vimov handles keyboard commands on every page.
- storage: the user's key mappings and settings. storage.local also holds three counts for the options page's "Your week with Vimov" card (links followed, pixels scrolled, tabs switched; this week and last only; src/shared/stats.js). They're never sent anywhere.
- sessions: "reopen closed tab" (X).
- clipboardRead: p and P open the URL on the clipboard (or search for its text), only when the user presses them. The clipboard is read in the background page (src/background.js, openClipboard) and nothing is kept.
- clipboardWrite: copying the page URL (yy) and link URLs (yf) from the background page when the page itself can't write to the clipboard.
- tabs, bookmarks, history: the vbar (o) and the "v" address-bar keyword search the titles and URLs of open tabs, bookmarks and history entries. Bookmarks are only read, never changed. Shift+Delete on a history result deletes that entry, only when the user asks. The toolbar button reads the active tab's URL to turn Vimov off or on for that site; it only edits the user's excluded-sites setting in storage.
- topSites: with nothing typed, the vbar (o) lists the user's most visited sites, as on Firefox's new-tab page. They're read when the box opens and nothing is kept.
- search: web searches from the vbar use the user's own search engines through search.search().
- browserSettings: Vimov only reads browserSettings.verticalTabs (src/background.js, src/options/options.js) to decide whether J or K goes to the next tab, and never sets any browser setting. The background page keeps that boolean in storage.local for content scripts. In Zen Browser, which locks that setting off, it comes from the `zen` field of runtime.getBrowserInfo() (Vimov.isZen in src/shared/defaults.js).

Site icons beside vbar results are the ones Firefox already provides as data: URLs (tabs' favIconUrl, and topSites with includeFavicon). They're held in memory in the background page and never stored or fetched; private tabs' icons are left out.

Screenshots (:screenshot, src/content/screenshot.js), when the user asks: the page scrolls a screen at a time; the background page captures each with tabs.captureVisibleTab, joins them on an OffscreenCanvas (src/stitch.js) and opens a tab (src/shot/) to copy or save the PNG. The images stay in memory until that tab closes, never stored or sent.

Search results are matched in the background page (src/sources.js) and drawn in a closed shadow root on the page; nothing is stored or sent anywhere.

On first install (not updates), Vimov opens a welcome page (src/welcome/welcome.html) listing its keys.

To try it, load the add-on, open any page and press ? for the list of keys, f for link hints or o to search.
